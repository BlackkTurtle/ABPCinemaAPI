                    ABP CINEMA API - TECHNICAL DOCUMENTATION
                         Conference Hall Booking System

PROJECT OVERVIEW

The ABP Cinema API is a .NET 9 ASP.NET Core Web API solution designed to manage 
conference hall bookings and rental cost calculations. The system enables clients 
to search for available conference halls, make bookings, and calculate rental costs 
based on time slots and selected services.

Repository: https://github.com/BlackkTurtle/ABPCinemaAPI

BUSINESS REQUIREMENTS

1. CONFERENCE HALL MANAGEMENT
   - Add new conference halls with capacity and hourly rental rates
   - Update hall information (capacity, rental rates, available services)
   - Delete conference halls from the system
   - Support multiple services per hall (projectors, Wi-Fi, sound systems, etc.)

2. BOOKING SYSTEM
   - Search for available halls based on date, time, and capacity requirements
   - Create bookings with specified duration and selected services
   - Automatic calculation of total rental cost based on time slots and services
   - Prevent overlapping bookings for the same hall

3. PRICING STRATEGY
   - Dynamic pricing based on time of day:
     * Standard hours (09:00 - 18:00): Base rate
     * Evening hours (18:00 - 23:00): 20% discount
     * Morning hours (06:00 - 09:00): 10% discount
     * Peak hours (12:00 - 14:00): 15% surcharge
   - Services add additional costs to base rental rate
   - Total cost = (Base Rate ? Time Duration ? Time Multiplier) + Services Cost

4. REPORTING AND ANALYTICS
   - Generate revenue reports for conference halls
   - Track booking history and hall utilization
   - Analyze service popularity and profitability

5. INITIAL DATA
   Conference Halls:
   - Hall A: Capacity 50 people, Base rate 2000 UAH/hour
   - Hall B: Capacity 100 people, Base rate 3500 UAH/hour
   - Hall C: Capacity 30 people, Base rate 1500 UAH/hour

   Services:
   - Projector: 500 UAH
   - Wi-Fi: 300 UAH
   - Sound System: 700 UAH

TECHNICAL SOLUTION ARCHITECTURE
================================================================================

1. ARCHITECTURE PATTERN: Layered Architecture with CQRS

   The solution implements a three-tier layered architecture:

   API Layer (ABPCinemaAPI.Api)
   - Controllers
      - HallController: Manages hall operations
      - AppointmentController: Handles booking operations
      - BaseApiController: Base class for unified response handling
   - Middleware
      - GlobalExceptionHandlerMiddleware: Centralized error handling
   - Configuration (Program.cs)

   Business Logic Layer (ABPCinemaAPI.BLL)
   - MediatR Handlers (CQRS Pattern)
      - Commands: CreateHall, UpdateHall, DeleteHall, CreateAppointment
      - Queries: GetAvailableHalls, GetHallsRevenueReport
   - Services
      - LoggerService: Logging infrastructure
   - Specifications
      - HallSpecifications: Query specifications for complex filtering
   - Mapping
      - AutoMapper profiles for DTO conversions
   - Exception Handling
       - Custom exception classes for specific error scenarios

   Data Access Layer (ABPCinemaAPI.DAL)
   - Entities
      - Hall: Conference hall entity with services relationship
      - Appointment: Booking entity linked to halls
      - Service: Available services entity
   - Repositories
      - GenericRepository: Base repository for CRUD operations
      - HallRepository: Hall-specific queries
      - AppointmentRepository: Appointment-specific queries
      - UnitOfWork: Transaction management
   - Persistence
      - AppDbContext: Entity Framework Core context
      - Seeding: Initial data population
      - Configurations: Entity configurations
   - DTOs: Data Transfer Objects for API contracts

2. DESIGN PATTERNS IMPLEMENTED

   a) CQRS (Command Query Responsibility Segregation)
      - Commands: CreateHall, UpdateHall, DeleteHall, CreateAppointment
      - Queries: GetAvailableHalls, GetHallsRevenueReport
      - Benefit: Separation of write and read operations, improved scalability
      - Implementation: MediatR library for command/query dispatching

   b) Repository Pattern
      - Generic repository for common CRUD operations
      - Specific repositories for complex domain queries
      - Unit of Work pattern for transaction management
      - Benefit: Data access abstraction, easier testing

   c) Specification Pattern
      - Complex query specifications (HallWithServicesSpec)
      - Encapsulates filtering, sorting, and includes logic
      - Benefit: Cleaner repository methods, reusable query logic

   d) DTO (Data Transfer Object) Pattern
      - Separate DTOs for input (Create/Update) and output (Get)
      - Protection of internal entity structure
      - API contract definition

   e) Dependency Injection
      - All services registered in IoC container
      - Constructor injection for loose coupling
      - Benefit: Better testability and maintainability

3. TECHNOLOGY STACK

   Core Framework:
   - .NET 9 (Latest LTS version)
   - ASP.NET Core (Web API framework)
   - Entity Framework Core (ORM for database access)

COST CALCULATION LOGIC

Algorithm:
1. Calculate duration in hours: (EndTime - StartTime).TotalHours

2. Determine time multiplier based on hour ranges:
   if (start_hour >= 06:00 AND start_hour < 09:00)
       multiplier = 0.90  // 10% discount
   else if (start_hour >= 09:00 AND start_hour < 12:00)
       multiplier = 1.00  // Standard rate
   else if (start_hour >= 12:00 AND start_hour < 14:00)
       multiplier = 1.15  // 15% surcharge
   else if (start_hour >= 14:00 AND start_hour < 18:00)
       multiplier = 1.00  // Standard rate
   else if (start_hour >= 18:00 AND start_hour < 23:00)
       multiplier = 0.80  // 20% discount
   else
       multiplier = 1.00  // Standard rate (outside operating hours)

3. Calculate base rental cost:
   base_cost = base_rate ? duration ? multiplier

4. Calculate services cost:
   services_cost = sum(all selected services costs)

5. Calculate total cost:
   total_cost = base_cost + services_cost

Example Calculation:
- Hall: "Hall 1", Base Rate: 2000 /hour
- Duration: 4 hours (10:00 - 14:00)
- Time slots: 10:00-12:00 (2 hours @ 1.00) + 12:00-14:00 (2 hours @ 1.15)
- Base cost: (2000 ? 2 ? 1.00) + (2000 ? 2 ? 1.15) = 4000 + 4600 = 8600 
- Services: Projector (500 ) + Wi-Fi (300 ) = 800 
- Total Cost: 8600 + 800 = 9400

SCALABILITY AND MAINTAINABILITY

1. CLEAN CODE PRINCIPLES (Robert C. Martin)

   a) Meaningful Names
      - Classes: HallController, CreateHallHandler, HallRepository
      - Methods: GetAvailableHalls, CalculateTotalCost
      - Variables: startTime, totalCost, selectedServices

   b) Single Responsibility Principle (SRP)
      - Each class has one reason to change
      - HallController: API routing
      - CreateHallHandler: Hall creation logic
      - HallRepository: Data access
      - LoggerService: Logging

   c) DRY Principle (Don't Repeat Yourself)
      - BaseApiController: Common response handling
      - GenericRepository: Shared CRUD operations
      - AutoMapper: Centralized DTOs conversion
      - Specifications: Reusable query logic

   d) Error Handling
      - Specific exception types for different scenarios
      - Global exception middleware for consistent handling
      - Meaningful error messages for debugging

   b) Add New Features
